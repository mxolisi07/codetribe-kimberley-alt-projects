# Shopping List API

A simple REST API built with Node.js and TypeScript for managing a shopping list. Users can add, view, update and delete the items they want to buy. It uses the built-in `http` module (no frameworks), validates all input, and returns JSON responses in one consistent shape.

## Features
- CRUD Operations: Create, Read, Update and Delete shopping list items.
- Automatic IDs: Each new item gets a unique, auto-incrementing numeric ID.
- Input Validation: Required fields, correct types and positive quantities are checked on every create and update.
- Consistent Responses: Every response is JSON in the same shape (except `204 No Content`, which has no body by definition).
- Reusable Error Handler: Bad input returns `400`, missing items return `404`, unsupported methods return `405`, and unexpected problems return `500` without crashing the server.
- In-Memory Storage: Items are kept in an array, so data resets whenever the server restarts.

## Technologies Used
- Node.js: JavaScript runtime for the HTTP server.
- TypeScript: Static typing for the whole project.
- ts-node and nodemon: Run TypeScript directly and restart on file changes during development.
- Postman: Manual endpoint testing.



## Usage
1. Start the development server:
   ```bash
   npm run dev
   ```
   This runs `nodemon --exec ts-node src/server.ts`.
2. The server runs on http://localhost:3000
3. Items are available at http://localhost:3000/items

Note: data is stored in memory, so the list is empty every time the server restarts.

## The Item Object
| Field | Type | Rules |
|---|---|---|
| `id` | number | Generated by the server, cannot be set by the client |
| `name` | string | Required, non-empty |
| `quantity` | number | Required, greater than 0 |
| `purchasedStatus` | boolean | Required, `true` or `false` |
| `unit` | string | Required, non-empty (for example `"L"`, `"kg"`, `"pcs"`) |
| `category` | string | Required, non-empty (for example `"Dairy"`) |
| `notes` | string | Required, may be an empty string |

Example:
```json
{
  "id": 1,
  "name": "Milk",
  "quantity": 2,
  "purchasedStatus": false,
  "unit": "L",
  "category": "Dairy",
  "notes": "Full cream"
}
```

## API Endpoints
| Method | Endpoint | Description | Success |
|---|---|---|---|
| POST | `/items` | Add a new item | `201 Created` |
| GET | `/items` | Get all items | `200 OK` |
| GET | `/items/:id` | Get a single item by ID | `200 OK` |
| PUT | `/items/:id` | Update an item (send only the fields to change) | `200 OK` |
| DELETE | `/items/:id` | Delete an item | `204 No Content` |

### POST /items
All six fields are required.

Request body:
```json
{
  "name": "Milk",
  "quantity": 2,
  "purchasedStatus": false,
  "unit": "L",
  "category": "Dairy",
  "notes": "Full cream"
}
```

Response `201`:
```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Milk",
    "quantity": 2,
    "purchasedStatus": false,
    "unit": "L",
    "category": "Dairy",
    "notes": "Full cream"
  }
}
```

### GET /items
Response `200`:
```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "name": "Milk",
      "quantity": 2,
      "purchasedStatus": false,
      "unit": "L",
      "category": "Dairy",
      "notes": "Full cream"
    }
  ]
}
```

### GET /items/:id
Returns one item inside `data`. Returns `404` if the item does not exist and `400` if the ID is not a whole number.

### PUT /items/:id
A partial update: send at least one field, and only those fields are changed.

Request body (for example, checking an item off):
```json
{ "purchasedStatus": true }
```

Response `200`: the full updated item inside `data`.

### DELETE /items/:id
Returns `204 No Content` with an empty body when the item is deleted, and `404` if it does not exist.

## Response Format
Success:
```json
{ "success": true, "data": { } }
```

Error:
```json
{
  "success": false,
  "error": {
    "message": "Validation failed",
    "details": ["name must be a non-empty string"]
  }
}
```
`details` only appears when there is a list of problems, such as validation errors.

### Status Codes
| Code | Meaning | Example |
|---|---|---|
| 200 | OK | Item found or updated |
| 201 | Created | Item added |
| 204 | No Content | Item deleted |
| 400 | Bad Request | Missing or invalid fields, invalid JSON, non-numeric ID |
| 404 | Not Found | Item ID or route does not exist |
| 405 | Method Not Allowed | For example `PATCH /items/1` |
| 500 | Internal Server Error | Unexpected server problem |

## Testing with Postman
Items are stored in memory, so create an item with POST first after every server restart.

1. Add a New Item:
- Method: POST
- URL: http://localhost:3000/items
- Body: select raw and choose JSON, then enter:
```json
{
  "name": "Milk",
  "quantity": 2,
  "purchasedStatus": false,
  "unit": "L",
  "category": "Dairy",
  "notes": "Full cream"
}
```
- Send the request. You should get `201` with the new item, including its `id`.

2. Get All Items:
- Method: GET
- URL: http://localhost:3000/items
- You should get `200` with a list of items.

3. Get One Item:
- Method: GET
- URL: http://localhost:3000/items/1
- Replace `1` with the ID of the item. You should get `200` with that item.

4. Update an Item:
- Method: PUT
- URL: http://localhost:3000/items/1
- Body: raw, JSON, for example:
```json
{ "quantity": 3, "purchasedStatus": true }
```
- You should get `200` with the updated item.

5. Delete an Item:
- Method: DELETE
- URL: http://localhost:3000/items/1
- You should get `204 No Content`. A `204` has an empty body, so check the status code at the top of the response.
